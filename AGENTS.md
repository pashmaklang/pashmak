# Repository guidance

## Project map

Pashmak is a programming language interpreter implemented in Python.

- `src/pashmak.py` is the interpreter command line entry point.
- `src/core/` contains the Python runtime: `lexer.py` and `parser.py` process source, `program.py` executes parsed commands, `function.py` and `class_system.py` implement callable and class behavior, `modules.py` stores bundled Pashmak modules, and `jit.py` handles parsed-code caching.
- Other directories under `src/` contain built-in Pashmak modules. `src/stdlib/` is loaded automatically; importable modules follow their directory/file path (for example, `src/sys/path.pashm` provides `sys.path`).
- `tests/` contains `.pashmt` regression tests and supporting fixtures. The tests are grouped by language feature and module.
- `doc/` contains user documentation and the developer guide; `examples/` contains sample programs; `scripts/` contains project automation written in Pashmak and shell.

For deeper architecture details, consult `doc/13_dev_guide/`. For contribution and test format details, consult `CONTRIBUTING.md`.

## Development commands

Run the interpreter from the repository root:

```sh
python3 src/pashmak.py [script.pashm]
```

Run the regression suite with:

```sh
make test
# or
python3 tests/run.py
```

When changing or adding `.pashm` module source, regenerate the embedded module table:

```sh
make module
```

This command writes `src/core/modules.py`; do not edit that generated file by hand. Review the generated diff and include it when it reflects intended module-source changes.

Other Make targets include `make compile` (PyInstaller executable), `make speed-test`, `make pylint`, and `make clean`. `make all` runs module bundling, header updates, tests, and the speed test; note that `make update-headers` changes headers across source, test, and script files, so use it only when those changes are intended. See `Makefile` for exact target behavior.

## Change workflow

- Keep changes scoped to the requested behavior and follow existing conventions in the affected area. The Python core and Pashmak language/module code are separate layers; make a change in the layer that owns the behavior.
- For a language or runtime behavior change, add or update a focused `.pashmt` regression test. The runner in `tests/run.py` discovers these recursively. Test sections include `--file--` and `--test--`; optional assertions include `--output--`, `--vars--`, `--mem--`, `--exit-code--`, and `--with-error--`. Assertion values use Python syntax. Read `CONTRIBUTING.md` for the complete format.
- For a user-visible feature or changed behavior, update the matching documentation under `doc/`; standard-module documentation generally belongs under `doc/10_modules/`. Record release-facing changes under the `next release` section of `CHANGELOG.md`, following its existing categories.
- Put new built-in modules under `src/` using the import path as the directory/file structure and the existing namespace conventions. Then run `make module` so the runtime's generated bundle stays in sync.
- Preserve cross-platform behavior where paths, shell commands, encodings, or file operations are involved. The project documents and tests Windows path/import behavior.
- Follow `CONTRIBUTING.md`, `SECURITY.md`, and the relevant developer guide when their details apply. Do not add dependencies or claim a Python-version requirement unless the project configuration/documentation establishes it.

## Working safely in this checkout

- Inspect `git status` and the relevant diff before editing. Preserve pre-existing user changes; do not reset, overwrite, or reformat unrelated work.
- Avoid hand-editing generated or cached artifacts. In particular, `src/core/modules.py` is generated by `make module`; Python cache directories are disposable runtime artifacts.
- Do not include credentials, private data, or local environment values in source, tests, documentation, or generated files.
- Run the narrowest relevant checks for the change, then the full `make test` suite when practical. Report checks that could not be run and why. Do not run broad mutating targets such as `make all` just for convenience; inspect their effects first.
